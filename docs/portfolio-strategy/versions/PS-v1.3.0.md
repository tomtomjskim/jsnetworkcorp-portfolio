# PS-v1.3.0 — First Real Target Adapter

Date: 2026-08-17
Status: current strategy snapshot
Parent: `PS-v1.2.0`

## Trigger

The portfolio received its first concrete target-role application case: a backend-centered data-team role focused on Internal Tools, AX, developer/operations tooling, backoffice, API, web UI, knowledge/AI workflow, and repetitive-work automation.

The source arrived through a private referral context. Company/internal-referral details remain outside the public portfolio repository.

## Core Decision

Do not create a new factual resume for the target.

Create a **target adapter** that changes:

- headline,
- summary emphasis,
- requirement-to-evidence mapping,
- public repository ordering,
- reading path.

It must not change:

- historical facts,
- responsibility level,
- claim status,
- metrics,
- public/private boundaries.

## Recommended Header

> **Backend Engineer | 업무시스템 · 내부도구 · AX/개발자동화**

### Why this header survived adversarial review

- `Backend Engineer` preserves the candidate's strongest long-term identity.
- `업무시스템` keeps the MES/commerce/business-system foundation visible.
- `내부도구` maps directly to the target's internal developer/operations-tool requirement.
- `AX/개발자동화` explains the recent public tooling work without claiming ML/model-engineering specialization.

Rejected alternatives:

### `AI Engineer`

Rejected because it can imply model training, inference, RAG platform, or ML specialization beyond current evidence.

### `Full-Stack Engineer` as the primary title

Rejected because frontend breadth is relevant but backend remains the strongest defensible career identity. Web/admin breadth is better demonstrated in the body.

### Stack-heavy headline

Rejected because the target explicitly values the ability to choose and build tools over a specific framework list.

## Target Priority

```text
P0    target resume/application adapter
P1    target GitHub portfolio projection
P1.5  selected public-repo current validation
P2    interview evidence / source-confirm only where target value is material
P3    web/PDF only if requested or clearly useful
```

This does not replace the general delivery priority of PS-v1.2.0; it defines how an actual target consumes the system.

## Requirement Model

High-priority target capabilities:

1. backend/business systems,
2. internal developer/operations tools,
3. AI/AX workflow and practical automation,
4. admin/backoffice and API delivery,
5. enough web frontend breadth to complete internal tools,
6. product/work-knowledge AI usage systems,
7. repeated development/operations automation,
8. fast adoption of useful technologies without framework fixation.

## Evidence Ordering

General backend portfolio:

```text
Career cases
→ StackForge Atlas
→ target-dependent tooling
```

Internal Tools / AX target:

```text
Career foundation
→ harness-kit
→ codex-workflow-skills
→ StackForge Atlas
```

Reason:

- `harness-kit` most directly answers the target's developer-internal-tool requirement,
- Codex Workflow Skills answers AI workflow/automation,
- StackForge Atlas remains the engineering-quality guardrail.

Repository order is a relevance projection, not a quality ranking across all roles.

## Review Result

Review method:

- recruiter,
- hiring-manager/data-team-lead,
- future-teammate.

First-pass finding:

- header itself was acceptable,
- summary was too process/jargon dense,
- frontend breadth needed to be concrete but not inflated,
- public R&D versus production AX ownership needed to remain explicit.

Applied changes:

- problem/repeated friction comes before workflow terminology,
- AI verification and unverified limitations are separated into a second sentence,
- frontend wording is framed as `업무·관리자 화면 + API + 데이터 흐름`,
- `AI Engineer`, production AX platform, model/RAG/inference, and frontend-specialist claims remain excluded.

Public target documents contain only generalized role characteristics.

## Main Hypothesis

A company-specific application should become stronger by **changing evidence selection and ordering, not by manufacturing company-specific experience**.

Expected target reading path:

```text
Backend career identity
→ actual business-system judgment
→ internal-tool problem solving
→ AI-assisted automation with verification
→ public source/test evidence
```

## Failure Conditions

PS-v1.3.0 fails if:

- AX wording pushes backend career evidence below the first screen,
- public R&D is mistaken for employer production work,
- AI tool names become more prominent than problems solved,
- frontend breadth is inflated into specialist expertise,
- target adaptation creates new unsupported factual claims,
- a generic target adapter is submitted without the authoritative full resume chronology.
