# PS-v0.9.0 — Initial Evidence-First Multi-Output Strategy

Date: 2026-08-17
Status: superseded reference

## Thesis

Build one evidence-first canonical career dataset and project it into resume, cover letter, PDF, web portfolio, and protected interview material.

## Strengths

- prevents factual drift between application surfaces,
- emphasizes problem, constraints, responsibility, decision, verification, and impact,
- supports engineering dossier and company-targeted views,
- introduces explicit claim/evidence and redaction gates,
- gives web and PDF enough structure for technical deep dives.

## Weaknesses

- does not provide a strict delivery priority among text, PDF, and web,
- can encourage premature investment in visual rendering,
- treats GitHub mainly as evidence linked from other surfaces rather than a portfolio surface itself,
- may duplicate repository explanations in a custom website before repository READMEs are strong enough.

## Output Model

```text
Canonical evidence
├─ resume
├─ cover letter
├─ PDF
├─ web
└─ interview deep dive
```

## Keep for Future Comparison

This version remains useful when comparing whether a highly designed PDF/web experience produces enough hiring value to justify its additional maintenance cost.
