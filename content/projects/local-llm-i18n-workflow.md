# Local LLM i18n Workflow

version: PF-v1.0.2
updated: 2026-08-19
visibility: public-sanitized
status: draft

## Summary

다국어 언어팩을 사람이 언어별 번역기에서 반복 번역하고 코드에 복사·입력하던 작업을, 내부망의 로컬 LLM과 별도 변환 프로그램으로 분리해 실제 개발 업무에 적용한 사례입니다.

이 사례의 목적은 대형 모델 성능을 보여주는 것이 아니라 **제한된 하드웨어와 내부 개발 환경에서도 반복 업무를 줄이는 수준의 로컬 AI 자동화를 실용적으로 적용한 것**입니다.

## Problem

프론트 화면의 텍스트는 i18n key/value 형태로 분리되어 있었지만 실제 다국어 언어팩 작성은 수작업 비중이 컸습니다.

```text
한국어 문장 확인
→ 언어별 번역기 실행
→ 결과 복사
→ 코드 입력
→ 언어별 반복
→ PHP/JSON 언어팩 반영
```

영어·일본어·중국어를 반복 처리하면서 번역과 복사·입력에 시간이 들었고, 대량 작업에서는 사람이 같은 형태의 단순 작업을 계속 수행해야 했습니다.

## Implementation

내부 개발 PC에 Ollama와 Gemma 3 계열의 소형 모델을 구성하고 Python 서버에서 로컬 추론을 수행했습니다.

```text
한국어 key/value
→ 내부망 Python translation server
→ Ollama / Gemma 3
→ 영어·일본어·중국어 번역 초안
→ 별도 language-pack program
→ PHP language pack
→ JSON 변환
→ 사람 검수·반영
```

LLM 호출과 언어팩 파일 생성·JSON 변환은 하나의 프로그램에 모두 묶지 않고 별도 책임으로 나눴습니다.

## Constraints

실행 환경에는 전용 GPU가 없었고 모델 크기도 작았습니다. 따라서 처리 속도와 번역 품질에 분명한 한계가 있었습니다.

- CPU 기반 추론으로 대량 처리 throughput이 높지 않음
- 소형 모델 특성상 일부 문장은 사람이 다시 확인해야 함
- 완전 자동 번역이나 번역 품질 보장을 목표로 하지 않음

이 제약을 감안해 사람이 결과를 검수하는 흐름을 유지했습니다.

## Practical Result

도입 후 언어별 번역기를 개별 실행하고 결과를 다시 코드에 옮기는 반복 작업을 줄일 수 있었습니다. 번역 초안 생성과 다른 개발 작업을 병행할 수 있었고, 프론트 개발자도 실제 언어팩 작업에 반복적으로 사용했습니다.

정확한 생산성 향상률이나 번역 정확도는 측정하지 않았기 때문에 공개 수치로 사용하지 않습니다.

## Engineering Point

이 사례에서 중요한 판단은 "어떤 모델을 사용했는가"보다 다음에 있습니다.

1. 반복적인 번역·코드 입력을 자동화 대상으로 식별
2. 외부 서비스가 아니라 내부망 로컬 추론을 선택
3. 번역과 파일 생성·변환 책임을 분리
4. 작은 모델과 CPU 환경의 한계를 인정하고 사람 검수를 유지
5. 실제 개발자가 계속 사용할 수 있는 수준으로 업무 흐름에 연결

## Evidence Boundary

공개 가능한 근거:

- 다국어 i18n 구조와 언어별 PHP/JSON 결과물의 존재
- 로컬 번역 흐름의 sanitized architecture
- 실제 개발 업무에서 사용했다는 역할·사용 범위

공개하지 않는 근거:

- private 번역 서버 저장소와 내부 경로
- 회사 내부망 주소나 실행 환경 상세
- 원문 언어팩 전체 데이터

## What This Does Not Claim

- 번역 정확도를 보장했다고 주장하지 않습니다.
- 모든 서비스 문구가 자동으로 번역됐다고 주장하지 않습니다.
- 외부 번역 비용 절감률을 주장하지 않습니다.
- 모델 학습·파인튜닝 경험으로 표현하지 않습니다.
- 조직 전체의 공통 번역 플랫폼으로 확대하지 않습니다.

## Interview Angle

면접에서는 다음 질문에 대응할 수 있는 사례로 사용합니다.

- 로컬 LLM을 실제 업무에 적용한 경험이 있는가?
- 작은 모델과 제한된 인프라를 어떻게 실용적으로 사용했는가?
- 자동화 품질이 충분하지 않을 때 사람 검수를 어디에 두었는가?
- 단순 반복 업무를 어떤 기준으로 프로그램화했는가?
