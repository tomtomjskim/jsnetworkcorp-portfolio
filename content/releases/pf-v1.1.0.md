updated: 2026-07-19
visibility: public-sanitized
status: release-candidate

## Goal

Shift the public portfolio from broad technology and architecture themes to three representative problem-solving cases that a hiring reviewer can understand quickly.

## Primary cases

1. Commerce state consistency
2. MES requirement systemization
3. Legacy PHP change-impact analysis

## Positioning change

### Previous

Backend / full-stack engineer with AI-assisted workflow and agent tooling capability.

### Current

PHP/MySQL backend engineer for commerce, logistics, and manufacturing business systems, with an operational approach that checks existing code, data states, permissions, admin workflows, batch jobs, and external API effects before changing production features.

## Completed scope

- Reordered the public project model around three primary cases.
- Rewrote the home Hero around PHP/MySQL operational backend work.
- Limited the home page to the three primary cases.
- Reframed case cards to expose the problem before the technology stack.
- Reordered case details into problem, decision boundary, change, verification, and public evidence boundary.
- Added a legacy PHP impact-analysis project and evidence-screen metadata.
- Rewrote the commerce and MES content sources around concrete analysis and verification processes.
- Moved live-commerce, AI workflow, and DB MCP material into supporting-case positions.

## Public evidence boundary

This release does not include:

- private project or customer names,
- real orders, payments, shipments, production, quality, inventory, or account data,
- table names, status codes, endpoints, credentials, payloads, logs, or server values,
- private repository links or protected evidence maps,
- unverified quantitative improvements,
- unsupported claims of architecture, financial payout, full modernization, or production ownership.
